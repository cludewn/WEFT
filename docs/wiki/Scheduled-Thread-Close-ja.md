# 予約クローズ

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Scheduled-Thread-Close)

予約クローズは、投稿が続いていても指定した時間の経過後に議論を終了したい場合に使います。例えば、時間を区切った質問スレッドを2時間後にクローズするよう予約できます。無投稿期間を条件にする場合は[自動クローズ](Automatic-Close-ja)を使用します。

1件の予約で将来のクローズを単発で予約します。実行時は手動と同じく、[ロックせずアーカイブ](Thread-Lifecycle-ja)します。スレッドの削除や、以後のDiscordでのアーカイブ解除を防ぐ機能ではありません。予約の保存時にはクローズせず、後のクローズ成功も保証しません。

<a id="create-replace-and-inspect"></a>

## 予約を作成して確認する

開いていてロックされていない、対応する公開・アナウンススレッド、アクセス可能な非公開スレッド、フォーラム投稿で使用します。実行者とWEFTの両方に、現在の「チャンネルを見る」と「スレッドの管理」権限が必要です。

1. 対象スレッド内で[`/thread close-after`](Commands-Thread-ja#thread-close-after)を選び、`after`に`2h`を入力して実行すると、2時間後のクローズを予約できます。`after`は必須の文字列で、正の整数と`m`・`h`・`d`を1組使い、1分～365日（1日は24時間）で指定します。予約投稿の`at`オプションは使用できません。
2. 応答を読み、返された予約IDと実行日時を控えます。IDは調査時の識別に使用します。このページのコマンドはIDを指定せず、実行したスレッドの現在の予約を操作します。
3. 同じスレッド内で[`/thread status`](Commands-Thread-ja#thread-status)を引数なしで実行し、予約クローズ欄が意図した日時かを確認します。自動クローズの各欄は、別のポリシーの情報です。

**実行登録**とは、保存した予約クローズを予定日時にWEFTのスケジューラが処理できるようにする実行準備です。予約の保存や、実際のアーカイブとは別です。登録未確認の応答では、再作成せず保存済み予約を確認してください。期限を過ぎたままなら[下記の結果確認](#execution-results)へ進みます。

| 作成結果                 | 意味と次の行動                                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 作成・置換済み           | 予約と日時の保存が確定しています。この時点ではクローズしません。返された日時とstatusを確認します。                                     |
| 保存済み・実行登録未確認 | 保存は確定しており、WEFTが実行登録を確認・修復できます。予約を保持し、statusを確認します。この応答だけを理由に置き換えないでください。 |
| 保存未確認               | 保存・未保存のどちらも確定していません。再試行前にstatusと運用記録を確認します。                                                       |

**現在の予約はスレッドごとに1件です。** 待機中の予約を変更するには、先に`/thread status`で現在の日時を確認します。次に`/thread close-after`の`after`へ新しい相対時間を入力して実行し、新しい応答と日時を確認してください。待機中の予約を置き換える操作であり、2件目を追加するものではありません。実行中（`EXECUTING`）の予約は置換できません。

<a id="cancel-or-close-now"></a>

## 予約を取り消す・今すぐクローズする

待機中のクローズを止めるには、対象スレッド内で[`/thread cancel-close`](Commands-Thread-ja#thread-cancel-close)を引数なしで実行します。結果を読み、同じスレッドで`/thread status`を引数なしで実行して現在の予約を確認してください。

対応スレッドなら、アーカイブ済み・ロック中でも取消できます。実行者に「チャンネルを見る」と「スレッドの管理」が必要ですが、WEFTの変更権限は不要です。

| 取消結果       | 意味と次の行動                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 取消済み       | 確認済みの応答を保持します。取り消した予約を根拠とするクローズは実行しません。                 |
| 現在の予約なし | 正常な変更なしです。以前のクローズの結果まで確認できるわけではありません。                     |
| すでに実行中   | 実行中のクローズは取り消せません。実際のスレッドと[実行結果](#execution-results)を確認します。 |
| 取消未確認     | 次の変更前にstatusと運用記録を確認します。取消済みと判断しないでください。                     |

今すぐクローズする場合は、[`/thread close`](Commands-Thread-ja#thread-close)を引数なしで実行し、[手動クローズの結果確認](Thread-Lifecycle-ja#close-one-thread)に従ってください。一括クローズで選択した対象も含め、有効な手動クローズは待機中の予約を取り消してから状態変更を試みます。**確定した取消は、その後のクローズが失敗・処理継続中でも戻りません。** 実行中の予約や取消未確認の場合は、新たなクローズを開始しません。

取消は自動クローズからの除外ではありません。[`/thread track`](Commands-Thread-ja#thread-track)で個別除外を解除したり、[`/thread untrack`](Commands-Thread-ja#thread-untrack)で個別除外を設定したり、親チャンネルの自動クローズ設定を変更したりしても、この予約は取り消しません。

<a id="execution-results"></a>

## 予定日時後の結果を確認する

実行時にDiscordの現在の状態とWEFTの権限を再確認します。クローズ済み、すでにアーカイブ済み、または削除・ロック・アクセス変更・障害などでクローズできない結果になり得ます。保存時の権限は将来の権限を保証しません。結果の確認や、開いたままのスレッドの調査は次の順で行います。

1. 返された実行日時と現在時刻を照合し、Discord上の実際のアーカイブ状態と名前を確認します。特にプレフィックス無効時は、名前だけではアーカイブ成功を判断できません。
2. スレッド内で`/thread status`を引数なしで実行し、予約クローズ欄を確認します。
3. 次の表で、現在の状態に合う確認へ進みます。

| 現在確認できる状態         | 次の確認・対処                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 実行待ち（`ACTIVE`）       | 予定日時前なら待機します。期限超過なら現在のスレッド状態と権限を確認します。実行条件を満たす予約でも、実行登録の修復やDiscordの待機で遅れる場合があります。[停止後の実行と再試行](#execution-and-downtime)も参照してください。 |
| 実行中（`EXECUTING`）      | 置換・取消を試みず、スレッドを確認します。解決しない場合は[スレッドの遅延の確認](Troubleshooting-ja#thread-delays)へ進みます。                                                                                                 |
| 現在の予約なし             | statusは終了履歴を表示しません。「なし」だけでは、その試行の完了・失敗・取消は判断できません。Discordと運用記録を照合します。                                                                                                  |
| クローズ完了を確認できない | 削除、ロック、WEFTのアクセス・「スレッドの管理」権限の喪失、状態反映の処理継続を確認します。特定できた原因だけを修正し、結果未確認なら新たな予約や手動クローズの前に調べてください。                                           |

`/thread status`は、処理継続中のクローズ・状態反映すべてを追跡するものではありません。現在の状態だけで解決しない場合は、予約ID、最初の応答、実行日時、現在のスレッド状態を保持し、ホスト運用者が[アプリの実行・結果確認ログ](Operations-ja#inspect-operation-logs)と[DB監査履歴](Audit-and-Privacy-ja#audit-storage-reference)に照合します。ログでは、この予約の実行結果と、保存予約の定期的な実行準備を区別してください。定期確認の成功だけではクローズ完了を判断できません。Discord通知がないだけでは失敗の根拠になりません。処理継続中・結果未確認には[結果の見方](Troubleshooting-ja#result-states)を使用してください。

<a id="execution-and-downtime"></a>

## 停止後の実行・遅延・再試行

条件を満たす失敗は再試行されるため、試行が1回だけとは限りません。再試行でも現在の状態を確認し、過去のDiscord変更をそのまま繰り返すとは限りません。

- 再起動後も、実行条件を満たす期限超過の予約は実行する場合があります。**投稿の60分・15分の猶予期間は予約クローズに適用しません。**
- 中断されたクローズは、起動時に再確認付きの再試行へ戻す場合があります。実行指示が再度届いても、現在の状態を再取得してからDiscordの変更を判断します。
- レート制限や定期的な修復で遅れる場合があり、正確な秒の実行は保証しません。
- スケジューラからクローズ処理への実行指示が一時的に失敗した場合、再試行回数には上限があります。ただし、予約が`ACTIVE`のままなら後の修復で再登録する場合があり、1回の再試行上限だけで`FAILED`になったとは判断できません。
- 確認済みの実行・再試行・失敗は監査します。Discord通知がないだけでは失敗の根拠になりません。

直前に操作したスレッドで手動の再試行を考える場合は、[同一スレッドで約10分の待機が必要になる可能性](Thread-Lifecycle-ja#delays-and-safe-observation)を考慮してください。待機中に同じスレッドを繰り返し操作しないでください。先に予約、実際のスレッド、処理継続中の操作を確認します。予約を作り直すと待機中の予約を置き換える場合があり、前の処理の完了を促すことにはなりません。

正確な動作は[`close-after`](Commands-Thread-ja#thread-close-after)、[`cancel-close`](Commands-Thread-ja#thread-cancel-close)、[`status`](Commands-Thread-ja#thread-status)を参照してください。競合や名前変更の遅延は[スレッド管理](Thread-Lifecycle-ja#delays-and-safe-observation)で説明します。
