# 監査とプライバシー

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Audit-and-Privacy)

WEFTは、管理操作の変更や実行結果を調べるための**監査履歴**をPostgreSQLへ保存します。Discordチャンネルへの**監査通知**も任意で有効にできます。保存履歴とDiscord通知では、役割と保証が異なります。

| 記録                  | 用途                                                        | 制約                                                                                         |
| --------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| PostgreSQLの監査履歴  | 記録された変更と結果を調べます。                            | 一部の失敗記録は保存できない場合があり、記録がないだけでは操作がなかったとは判断できません。 |
| 任意のDiscord通知     | DBを読まず、新たに確定した監査を確認します。                | 通知が届かない場合があり、正式な保存先ではありません。                                       |
| Discord標準の監査ログ | WEFTのスレッド変更理由など、Discord自身の記録を確認します。 | WEFTのDB履歴とは別のDiscordサービスです。                                                    |

<a id="what-is-recorded"></a>

## 監査対象

以下の**10種類**すべてが、保持処理と任意のDiscord通知の対象です。

| 監査対象                         | 記録する操作・結果                                                           |
| -------------------------------- | ---------------------------------------------------------------------------- |
| スレッド操作                     | クローズ・状態更新（自動処理を含む）とその結果                               |
| 予約クローズ                     | 予約クローズの作成・置換・取消、実行・再試行・失敗                           |
| 管理メッセージの変更             | 確認済み管理メッセージの作成・編集・編集時の削除検知                         |
| 単発の予約投稿                   | 単発予約の変更と実行結果                                                     |
| 定期投稿                         | 定期投稿の変更、実行回の結果、DST欠落、未実行範囲                            |
| 監査通知先の設定                 | 監査通知先の変更                                                             |
| リンクプレビューの設定           | モード変更（プレビュー内容・クリックは対象外）                               |
| サーバー設定と個別除外           | タイムゾーン、プレフィックス、自動クローズの各設定・親、個別除外             |
| 管理操作の失敗                   | 下記の条件を満たす、設定・除外・予約の変更や手動・一括クローズの準備での失敗 |
| 管理メッセージの送信・編集の失敗 | 対話式の送信・編集で確認できた失敗、または一部の処理だけが確定した結果       |

**すべての失敗が記録されるわけではありません。** 入力・対象・実行者の権限を確認できた管理操作について、DBへの変更が完了しなかったと確定できる失敗などを記録します。一部の操作では、必要な情報の取得、ボット権限、開いているスレッドの取得の失敗も対象です。例えば、自動クローズの親の有効化では対象スレッドの取得失敗、予約クローズの作成では実行者の権限確認後のボット権限不足を記録できます。すべての操作で、これらすべての失敗を記録するわけではありません。

不正入力、実行者の権限拒否・確認不能、通常の競合、WEFTが同じ対象の処理をすでに続けている場合は、この独立した管理失敗記録の対象外です。対話式の管理メッセージ送信・編集は別の失敗記録を使い、確認済みの失敗と`PARTIAL`を区別します。`PARTIAL`では、Discordへの反映とDB更新の未完了が確認できています。ただし、送信済み投稿の削除や変更前の内容への復元は、試みていないか、試みても拒否されています。エラーや応答の名前だけでは確認済みの失敗と判断せず、記録には対象となる失敗の根拠が必要です。

通常のサーバー管理では、まず応答と実際のDiscord状態を確認してください。運用者は[DB記録先一覧](#audit-storage-reference)から記録された根拠を調べます。履歴や通知がないことだけを理由に、再送信や再クローズを安全と判断しないでください。

<a id="stored-data-and-privacy"></a>

## 保存情報を保護する

サーバーのプライバシー要件に応じて、DB、[バックアップ](Backup-and-Recovery-ja)、通知先の閲覧者を制限してください。

| 情報                                 | 保存・公開範囲                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 実行者・Discord ID、日時、操作、結果 | 監査履歴に含まれる場合があります。                                                                                                         |
| 失敗の詳細                           | 対象となる失敗記録には操作・失敗段階・定義済みの理由を保存します。確認済み対象IDや、反映・削除・復元の根拠は記録の種類によって異なります。 |
| 対応するメッセージ内容と変更         | 管理メッセージの成功監査には内容全体と変更前後を含みます。予約内容・監査にも本文や画像URLを含む場合があります。                            |
| 自動クローズの活動                   | 本文ではなくメタデータです。                                                                                                               |
| プレビュー内容・クリック             | 専用の永続履歴・監査はありません。                                                                                                         |
| Discord通知                          | 限定したテキストのメタデータです。メンションを抑止し、本文・埋め込み内容・名前・任意の変更前後値・生エラー・認証情報は含めません。         |

確認済み管理失敗と管理メッセージ実行失敗の通知は、対象識別情報も除きます。他の記録元では対象IDを含む場合があります。WEFTの履歴保持処理では、Discordのコピーや古いバックアップは削除できません。

<a id="optional-discord-notifications"></a>

## Discord通知を設定・確認・無効化する

「サーバーの管理」権限が必要です。適切な閲覧範囲のテキスト・アナウンスチャンネルを選び、WEFTに現在の「チャンネルを見る」「メッセージを送信」を付与します。通知には実行者などのメタデータが含まれ、記録元によっては対象IDも含みます。

1. [`/config audit-log set`](Commands-Config-ja#config-audit-log-set)を選びます。`channel`ではDiscordのチャンネル候補から、意図した`#weft-audit`などの送信先を選択して実行します。
2. 応答で保存済み・変更なしが確定したかを確認します。[`/config audit-log show`](Commands-Config-ja#config-audit-log-show)を引数なしで実行し、意図したチャンネルIDか確認します。保存が`UNCONFIRMED`の場合は、再試行前に[結果未確認の調査](Troubleshooting-ja#result-states)を行ってください。
3. その後の実際の[監査対象変更](#what-is-recorded)と、届いた場合の通知を確認します。送信先の設定はテスト通知の送信成功の保証ではありません。
4. 通知がなければ、[通知の確認手順](Troubleshooting-ja#audit-notifications-missing)に沿って保存済み送信先、現在のアクセス、監査対象かどうか、運用記録を調べます。showは削除済みの送信先でも保存IDを表示します。通知がないことは操作失敗の証明ではありません。[通知と記録の限界](#evidence-limits)を参照してください。

通知を停止する場合は、[`/config audit-log disable`](Commands-Config-ja#config-audit-log-disable)を引数なしで実行します。応答を読み、`/config audit-log show`で送信先が無効になっていることを確認します。

DB監査と保持処理は継続します。過去の通知は削除せず、無効化時は通常、通知を送信しません。

<a id="retention"></a>

## 保持期間と適用範囲

| 保持対象                                    | 保持期間（日） | 適用条件                                                                      |
| ------------------------------------------- | -------------- | ----------------------------------------------------------------------------- |
| <!-- fact:audit-retention-days --> 監査記録 | 90             | 1日を24時間として計算します。保持期間は固定で、サーバーごとに変更できません。 |

| 保持処理の項目                                                  | 件数・間隔 | 適用条件                                     |
| --------------------------------------------------------------- | ---------- | -------------------------------------------- |
| <!-- fact:audit-source-count --> 保持処理の対象となる監査の種類 | 10種類     | 上記の監査対象すべてを含みます。             |
| <!-- fact:audit-sweep-hours --> 次回の削除処理までの間隔        | 24時間     | 前回の削除処理が終了した時点から計測します。 |
| <!-- fact:audit-batch --> 1回の削除バッチの上限                 | 500件      | 監査日時とIDの順に削除します。               |

起動直後に初回の削除処理を予定します。この処理のために稼働準備の完了を遅らせることはありません。確認ごとに基準時刻を1つ決め、現在から90×24時間より**厳密に古い**記録だけ削除します。
境界と同じ時刻は残します。バッチ処理や障害で削除が遅れるため、期限ちょうどの削除は保証されません。
ある記録元の削除処理が失敗しても通常操作を無効にせず、他の記録元の削除は続けます。失敗した記録元の残りは後の確認を待ちます。

削除するのは監査履歴だけで、予約、管理リソース、設定、復旧状態は変えず、削除通知も送りません。
保持期間をサーバーごとに変更することはできません。
他の保存先の本文、Discordのコピー、過去のバックアップを削除する保証ではありません。[バックアップ](Backup-and-Recovery-ja)も非公開データとして扱います。

<a id="evidence-limits"></a>

## 記録の有無から判断できること

- 実際に成功した設定変更は監査します。完全な変更なしや計測開始時刻だけの補完は設定変更履歴を作りません。
- 独立した確認済み管理失敗の記録では、不正入力・対象外・権限拒否や未確認・通常の競合・同じ対象ですでに続いている処理は対象外です。
- `PENDING`はWEFTが処理・確認を継続する状態、`UNCONFIRMED`は根拠不足です。応答の遅延や非同期処理のエラーだけで確認済み失敗にはなりません。
- スレッド操作・自動処理の結果には、`FAILURE`を含んでもDiscord上の変更を確定できていないものがあります。例えば`DISCORD_RECONCILIATION_UNCONFIRMED`は、WEFTがスレッド操作の結果を確認して完了できなかった状態です。それ以前のDiscord変更は行われた可能性があるため、次の変更前に実際のスレッドと運用記録を調べてください。
- 独立した失敗記録は通常操作の後に保存を試みます。障害・クラッシュ・終了期限で失う場合があり、後から補完しません。
- `PARTIAL`は過去の確認済み事実だけを示し、現在残る投稿状態は示しません。監査や通知がないだけでは、操作がなかった証明になりません。

通知時に現在の送信先とWEFTの閲覧・送信権限を確認し、重複低減付きで1回だけ送信を試みます。再試行、再送、過去分の補完、順序、厳密な1回限りの保証はありません。DB保存後のクラッシュで通知だけを失う場合があります。通知が届かなくても、保存済みの操作が取り消されることはありません。

<a id="audit-storage-reference"></a>

## 運用者向けのDB記録先一覧

DB監査履歴全体を閲覧するスラッシュコマンドや検索ツールは付属していません。PostgreSQLへアクセスできるホスト運用者が、現在のDB構造に合わせた読取専用SQLで調査します。以下は記録先の一覧であり、そのまま実行できる確認ツールではありません。保存した応答・日時と、記録の操作、実行者、記録があれば対象・予約ID、結果、失敗理由を照合してください。列は種類によって異なり、一部の失敗記録は意図的に対象識別情報を含めません。特定の試行を識別できない場合は結果未確認のままとし、後の設定値の一致から推測しないでください。

管理失敗記録では、操作内容と実行経路（例えば手動クローズか一括クローズの準備か）を表す23種類の固定識別子を使います。この操作・起点コードは、すべてのコマンド失敗の件数ではなく、設定・除外・予約の変更と、スレッド単位の手動・一括クローズの準備を分類するものです。操作コード・失敗段階・理由を組み合わせて読み、スレッドの実行結果や管理メッセージの実行結果は別の記録で調べてください。利用者に関わる対象条件は[上記の監査対象](#what-is-recorded)を参照してください。

| 監査対象                         | DBテーブル                               |
| -------------------------------- | ---------------------------------------- |
| スレッド操作                     | thread_audits                            |
| 予約クローズ                     | scheduled_thread_close_audits            |
| 管理メッセージの変更             | managed_message_audits                   |
| 単発の予約投稿                   | scheduled_message_audits                 |
| 定期投稿                         | recurring_message_audits                 |
| 監査通知先の設定                 | audit_log_destination_audits             |
| リンクプレビューの設定           | link_preview_audits                      |
| サーバー設定と個別除外           | guild_configuration_audits               |
| 管理操作の失敗                   | administrative_operation_failure_audits  |
| 管理メッセージの送信・編集の失敗 | managed_message_execution_failure_audits |

コマンド詳細は[`audit-log show`](Commands-Config-ja#config-audit-log-show)、[`set`](Commands-Config-ja#config-audit-log-set)、[`disable`](Commands-Config-ja#config-audit-log-disable)、不確定な操作は[トラブルシューティング](Troubleshooting-ja#result-states)を参照してください。
