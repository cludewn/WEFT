# 自動クローズ

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Automatic-Close)

自動クローズは、一定期間投稿のないスレッドを自動的にクローズする機能です。例えば、サポートの議論ごとに期限を指定せず、利用されなくなったスレッドを整理できます。手動操作と同じく、[ロックせずアーカイブ](Thread-Lifecycle-ja)します。

**親チャンネル**とは、スレッドが属するテキスト・アナウンス・フォーラムチャンネルです。親を有効にすると配下のスレッドへ設定を適用し、必要に応じて個別に除外できます。事前にWEFTで手動クローズしたり、管理記録を作成したりする必要はありません。初期状態では有効な親がないため、自動クローズする対象はありません。

<a id="enable-a-parent-then-exempt-individual-threads"></a>

<a id="set-up-and-verify-a-policy"></a>

## 自動クローズを設定する

サーバー設定の変更には「サーバーの管理」権限が必要です。個別スレッドの確認・除外には「スレッドの管理」権限が必要です。実際にクローズする際は、WEFTにも現在のアクセスとスレッド管理権限が必要です。最初は確認用の親チャンネルで設定してください。

<a id="set-inactivity-period"></a>

### 1. 無投稿期間を設定する

投稿のない状態が7日続いたスレッドをクローズするには、[`/config auto-close inactivity`](Commands-Config-ja#config-auto-close-inactivity)を選び、`value`に`7d`を入力して実行します。応答で、指定した期間が保存されたか、変更なしだったかを確認してください。

正の整数と`m`・`h`・`d`を1組使い、5分～365日で指定できます。既定値は7日です。この期間は、サーバー内の有効な親チャンネルに共通で適用します。

**設定済みの期間を変更する場合:** 期間を短くすると、記録済みの活動へ新しい閾値を適用します。全スレッドの計測をリセットする設定ではないため、既存のスレッドが早く対象になる場合があります。

<a id="choose-bot-activity"></a>

### 2. ボットの投稿を活動に含めるか選ぶ

ボットの投稿で無投稿期間を更新するには、[`/config auto-close bot-messages`](Commands-Config-ja#config-auto-close-bot-messages)を選び、`value`で`true`に対応する真偽値を選択します。含めない場合は`false`を選択します。既定値は`false`です。コマンドを実行し、応答でボットの投稿を含める設定か、含めない設定かを確認してください。

Discordシステムメッセージは、`true`でも数えません。他のイベントについては[活動として数えるもの](#what-counts-as-activity)を参照してください。

<a id="enable-parent"></a>

### 3. 対象の親チャンネルを有効にする

[`/config auto-close add-parent`](Commands-Config-ja#config-auto-close-add-parent)を選び、`channel`で対象のテキスト・アナウンス・フォーラムチャンネルをDiscordの候補から選択して実行します。例えばサポート用フォーラムを選ぶ場合も、意図した投稿先であることを確認してください。

応答で、有効化が確定したか、すでに有効だったかを確認します。新たに有効化した場合は、無投稿期間の計測開始時刻を設定・更新したスレッドの件数も表示します。これは計測開始の件数であり、クローズした件数ではありません。

WEFTは開いているスレッドを先に取得し、取得に失敗した場合は親を有効にしません。新たに有効となった対象は、有効化時点か、それより新しい活動時刻から計測します。有効化前の無投稿期間を数えて直ちにクローズすることはありません。

<a id="verify-setup"></a>

### 4. 保存した設定と個別スレッドを確認する

1. [`/config auto-close show`](Commands-Config-ja#config-auto-close-show)を引数なしで実行し、無投稿期間、ボット投稿の扱い、有効な親チャンネルを確認します。親は最大25件と残件数を表示するため、対象の親が表示されない場合は、次の手順で親の設定を確認してください。
2. 有効にした親のスレッド内で、[`/thread status`](Commands-Thread-ja#thread-status)を引数なしで実行します。そのスレッドに自動クローズが適用されるかどうか、親の設定、個別除外、無投稿期間、記録した活動時刻または計測開始時刻を確認します。予約クローズの有無も確認してください。
3. 無投稿期間にかかわらず残すスレッドは、[個別に除外](#exclusions-and-stopping)します。

クローズ後は、Discord上の実際のアーカイブ状態を確認してください。自動クローズはロックせずアーカイブします。無投稿期間は対象になるための閾値であり、定期確認やDiscordの待機があるため、正確な期限ではありません。[クローズの時期](#when-closing-can-happen)も参照してください。

設定やstatusが意図と異なる場合は、複数の設定を変更する前に[自動クローズの調査手順](Troubleshooting-ja#automatic-close-not-running)を確認してください。設定の保存だけでは、その後のクローズ成功は確定しません。

<a id="exclusions-and-stopping"></a>

## スレッドを除外する・設定を停止する

<a id="exclude-one-thread"></a>

### 1つのスレッドを自動クローズから除外する

個別のスレッド内で、[`/thread untrack`](Commands-Thread-ja#thread-untrack)を引数なしで実行します。「スレッドの管理」権限が必要です。除外設定を追加したら、同じスレッドで`/thread status`を実行し、個別除外と、そのスレッドに自動クローズが適用されるかどうかを確認してください。

再び対象にするには、[`/thread track`](Commands-Thread-ja#thread-track)を引数なしで実行し、`/thread status`で確認します。trackは除外を解除しますが、無効な親を有効にしません。有効な親で除外を解除した場合は、操作時点か、それより新しい活動時刻から計測します。すでに対象のスレッドでtrackを繰り返しても計測をリセットしません。どちらも明示的な予約クローズを変更しません。

<a id="disable-parent"></a>

### 親チャンネル全体で自動クローズを停止する

[`/config auto-close remove-parent`](Commands-Config-ja#config-auto-close-remove-parent)を選び、`channel`で対象の親チャンネルを候補から選択して実行します。応答で、無効化が確定したか、すでに未設定だったかを確認してください。`/config auto-close show`では残りの設定を確認します。親の表示は最大25件のため、表示されないことだけでは無効化を確認できません。対象の親に属するスレッド内で`/thread status`を実行すると、その親の設定を確認できます。

親の無効化や個別除外は、開始済みの処理の強制停止、アーカイブ解除、明示的な予約の取消を行いません。明示的な予約には[予約クローズの取消](Scheduled-Thread-Close-ja#cancel-or-close-now)を使用してください。

<a id="what-counts-as-activity"></a>

## 活動として数えるもの

| イベント                                         | 活動の扱い                                 |
| ------------------------------------------------ | ------------------------------------------ |
| 対象スレッドでの利用者（ボット以外）の投稿       | 数えます。                                 |
| WEFTを含むボットの投稿                           | `bot-messages`が`true`の場合だけ数えます。 |
| Discordシステムメッセージ                        | 常に対象外です。                           |
| リアクション、名前、スレッド設定、WEFT設定の変更 | 数えません。                               |

活動記録には本文ではなくメタデータを保存します。遅れて到着したイベントで記録時刻を過去へ戻しません。Discordの履歴を再走査したり、停止中に受信できなかった投稿をすべて補完したりする機能はありません。

<a id="measurement-baselines"></a>

## 記録された計測開始時刻を理解する

**計測開始時刻（baseline）**は、投稿がなくても無投稿期間の計測を始めるための時刻です。親の有効化、除外解除、開いた状態への復帰の検知、未記録の初期化で設定される場合があります。

| 操作する対象・条件とコマンド                                                                  | 計測時刻・除外設定への影響                                     |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 自動クローズが有効な親チャンネルに属する個別除外中のスレッドで`/thread track`を実行           | 操作時点から計測し、より新しい活動記録は保持します。           |
| 自動クローズが有効な親チャンネルに属する個別除外されていないスレッドで`/thread track`を再実行 | 計測を維持し、未記録の場合だけ補います。                       |
| 自動クローズが無効な親チャンネルのスレッドで`/thread track`を実行                             | 除外設定があれば解除しますが、計測は開始しません。             |
| 個別スレッドで`/thread untrack`を実行                                                         | 個別除外を設定し、活動時刻は保持します。                       |
| `/config auto-close remove-parent`で親チャンネルの自動クローズを無効化                        | 活動記録と個別除外を保持します。                               |
| `/config auto-close add-parent`で親チャンネルの自動クローズを再び有効化                       | 対象は再有効化時点から計測し、より新しい活動記録は保持します。 |

起動時に開いているスレッドを確認し、未記録の計測開始時刻の補完を試みます。新たに見えるようになったスレッドでも、古い作成時刻を使うとは限りません。クローズの時期を判断する場合は`/thread status`を確認してください。

時刻が未記録の場合は、親が有効であり、そのスレッドを除外する必要がないことを先に確認してください。「スレッドの管理」権限で[`/thread track`](Commands-Thread-ja#thread-track)を実行すると、欠けている計測開始時刻を補えます。その後、statusを再確認します。未記録ならここから計測を始めるもので、過去の投稿の復元や即時クローズではありません。繰り返しても既存の計測時刻は変えません。

<a id="when-closing-can-happen"></a>

## クローズの時期と実行を妨げる条件

記録した投稿・計測開始時刻に**現在の**無投稿期間を加えた時刻が、確認時刻以前になると対象です。スレッド作成からの経過時間ではありません。

初回確認は起動から5分後、その後は前回の終了から5分後に開始します。確認の長期化やDiscordの待機でさらに遅れる場合があります。期間は正確なクローズ期限ではありません。

実行前に現在のポリシー、対象の活動記録、実際の親・スレッド状態、WEFTの権限を確認します。実行待ち（`ACTIVE`）・実行中（`EXECUTING`）の予約クローズが優先され、自動クローズ側では取り消しません。すでにアーカイブ済み・条件外の対象はスキップする場合があります。失敗した試行は後の確認で再び対象となる場合があり、失敗したことだけでクローズ済みとは判断できません。

設定の確認とDiscord上の変更は別の処理です。確認後の設定・活動の変化が、開始しかけたクローズと重なる場合があります。設定の無効化だけで、処理中のクローズが停止したとは判断しないでください。保存済みプレフィックスや処理継続中の扱いは[スレッド管理の共通動作](Thread-Lifecycle-ja)に従います。

<a id="verify-a-policy-change"></a>

## 想定と異なる結果を確認する

サーバー設定は[`auto-close show`](Commands-Config-ja#config-auto-close-show)、個別の対象判定は[`thread status`](Commands-Thread-ja#thread-status)で確認します。どちらも処理継続中の状態反映をすべて表示するものではありません。設定の保存が未確認なら、再試行前に該当設定を調べてください。クローズされない場合は[症状別の確認](Troubleshooting-ja#automatic-close-not-running)、処理継続中の場合は[待機中の操作の確認](Troubleshooting-ja#thread-delays)を参照してください。
