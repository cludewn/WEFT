# 管理メッセージ

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Managed-Messages)

**管理メッセージ**は、WEFTが送信し、後から管理者が編集できるようにWEFTへ記録した投稿です。内容を更新する可能性があるお知らせなどに使います。ボットが送信したという事実だけでは、管理記録があるとは判断できません。

**埋め込み**は、タイトル・説明文・画像などを持つ整形されたカードです。本文だけ、対応する埋め込み1件だけ、または両方を作成できます。

| 用途                 | 本文                | 埋め込みの項目                                                    |
| -------------------- | ------------------- | ----------------------------------------------------------------- |
| 本文だけのお知らせ   | `09:30から会議です` | 空欄にします。                                                    |
| カード付きのお知らせ | `09:30から会議です` | タイトル`週次会議`、説明文`議題はピン留め投稿を参照`、色`#3366CC` |
| カードだけの投稿     | 空欄にします。      | タイトル`メンテナンス完了`                                        |

フォームには本文、埋め込みのタイトル・説明文・色・画像URLがあります。添付や複数の埋め込みには対応しません。すべての制限は[入力項目](#shared-form-rules)を参照してください。

<a id="before-sending"></a>

## 投稿先と権限を確認する

投稿先のサーバー内テキスト・アナウンスチャンネル、または開いている対応スレッドで実行します。アクセス可能な非公開スレッドやフォーラム投稿も対象です。実行者には「メッセージの管理」が必要で、同じ権限を持つ別の管理者も編集できます。

作成時はWEFTにも現在の閲覧・送信権限が必要です。スレッドでは「スレッドでメッセージを送信」、明示的な埋め込みには「埋め込みリンク」も必要です。アーカイブ済みスレッドは拒否し、送信のためのアーカイブ解除や非公開スレッドへの参加は行いません。

**送信を繰り返す前に、応答と実際の投稿の両方を確認してください。** 管理記録の保存が未確認でも、投稿が存在する場合があります。

<a id="send-text-or-an-embed"></a>

## 作成してメッセージIDを控える

1. 意図した投稿先で[`/message send`](Commands-Message-ja#message-send)を引数なしで実行します。Modal（入力フォーム）が開きますが、開くだけでは送信しません。投稿先を指定する引数はなく、実行したチャンネルを使用します。
2. 上の例を参考に、本文、埋め込み、または両方を入力します。本文だけのお知らせなら、本文に`09:30から会議です`を入力し、埋め込みの全項目を空欄にします。カードだけなら本文を空欄にし、表示可能な埋め込みのタイトル・説明文・画像のいずれかを入力します。
3. フォームを送信し、WEFTの応答と投稿先の実際のメッセージを確認します。
4. 成功が確定したら、返された**DiscordメッセージID**、またはコピーした投稿リンクを編集用に控えます。予約IDではなく、送信した投稿の識別情報です。

空白だけの本文は空へ正規化され、表示可能な埋め込みがあれば有効です。色だけの埋め込みは、**本文があっても無効**です。自動解析による利用者・ロールへのメンション通知は抑止します。通常のURLは使用できます。

<a id="check-the-send-result"></a>

### 再送の前に結果を確認する

確認済みの成功は、Discordへの送信とWEFTの管理記録の保存が確定したことを示します。実際の投稿に、入力した本文と対応する埋め込みが表示されているか確認してください。WEFT自身の投稿であるだけでは、管理登録の成功は判断できません。

- 入力不正が報告された場合は、`/message send`で新しいフォームを開き、[入力の規則](#shared-form-rules)に従って該当項目を修正します。
- Discordによる送信拒否が確定した場合、メッセージは送信されていません。現在の投稿先と権限を確認してから、再試行を判断します。
- 送信や管理登録が未確認、または削除が拒否・未確認の場合は、失敗と決めつけて再送・削除しないでください。実際の投稿を確認し、ホスト運用者が[確認できる情報](Troubleshooting-ja#available-checks)に従い、管理記録と監査履歴を照合します。[結果未確認の扱い](#permissions-and-uncertain-outcomes)へ進んでください。

<a id="edit-an-existing-managed-message"></a>

## 既存の投稿を編集して確認する

元の投稿と**同じサーバー・チャンネル**で実行します。実行者には「メッセージの管理」が必要です。WEFTには「チャンネルを見る」「メッセージ履歴を読む」権限が必要です。対象はWEFT自身が送信し、現在も編集できる投稿に限ります。変更後に明示的な埋め込みが残る実際の編集には「埋め込みリンク」も必要ですが、送信権限は不要です。アーカイブ済みのスレッドは編集対象にできません。

1. [`/message edit`](Commands-Message-ja#message-edit)を選び、`message`に控えたDiscordメッセージID、またはこのチャンネル内の厳密な`https://discord.com/channels/<server-id>/<channel-id>/<message-id>`形式のリンクを入力して実行します。確定したWEFT管理記録がある投稿が対象です。
2. 読み込まれた保存済みの本文・埋め込みを確認します。例えば、本文を`09:30から会議です`から`10:00から会議です`へ変更し、フォームを送信します。開いただけでは変更しません。
3. 応答と実際の変更後の投稿を確認します。変更成功時は保存内容の版番号（**リビジョン**）を1回増やします。現在の状態も一致する同一内容なら、変更なしも正常です。

本文を空にできるのは、表示可能な埋め込みが残る場合だけです。本文が残っていれば埋め込みの全項目を消して除去できます。表示内容すべてを空にはできません。

古いフォームになった場合は、新しいフォームを開いて現在の保存内容を確認します。Discordと保存内容が不一致の場合は調査が必要で、WEFTはどちらかを自動で書き換えません。編集・結果保存・復元が未確認のまま、次の変更を行わないでください。投稿と記録を先に確認します。`PARTIAL`でも現在どの内容が残っているかは判断できません。[編集の競合](#edit-conflicts-and-mismatches)と[結果未確認の扱い](#permissions-and-uncertain-outcomes)を参照してください。

<a id="deletion-and-scheduling"></a>

## 投稿を削除する・新たな投稿を予約する

WEFTに管理メッセージの削除コマンドはありません。権限がある場合はDiscordのメッセージ削除を使用します。WEFTは編集フォームの送信処理で不在を確認すると`DELETED`を記録しますが、削除を常時監視しません。削除検知時も保存内容とリビジョンは保持します。

後で投稿するには[予約投稿](Scheduled-Messages-ja)へ進んでください。予約の作成時には送信せず、予約を取り消しても送信済み投稿は削除しません。

<a id="shared-form-rules"></a>

## 入力項目と制限

送信・編集・予約作成・予約内容の編集で共通です。

| 入力項目                                           | 上限・形式                 | 検証・入力時の注意                                                          |
| -------------------------------------------------- | -------------------------- | --------------------------------------------------------------------------- |
| <!-- fact:payload-content --> 本文                 | 2000 Unicodeコードポイント | 空白の正規化より前に長さを確認します。                                      |
| <!-- fact:payload-title --> 埋め込みのタイトル     | 256 UTF-16コード単位       | 前後の空白を除き、空白だけなら未設定とします。                              |
| <!-- fact:payload-description --> 埋め込みの説明文 | 4000 UTF-16コード単位      | 前後の空白を除き、空白だけなら未設定とします。                              |
| カラーコード                                       | 6桁の16進数                | 先頭の`#`は任意です。`FF0000`と`#ff0000`はどちらも使用できます。            |
| <!-- fact:payload-image --> 画像URL                | 2048コード単位以内         | HTTP/HTTPSの絶対URLを使います。元の入力と正規化後の両方の長さを確認します。 |

- 本文の長さは空白の正規化前に確認します。空白以外を含む本文は、前後の空白・改行を保持します。
- 埋め込みのタイトル・説明文は前後の空白を除き、空白だけの項目は未設定にします。内部の空白は保持します。多くの絵文字はUTF-16で2単位です。Discordのフォーム側で別の入力上限が適用される場合もあります。
- 編集時の色は大文字の`#RRGGBB`で表示します。色は6桁の16進数で、`#`は任意です。
- 画像URLは前後の空白を除いて構文を正規化します。画像のダウンロードや内容確認は行いません。
- 作成できる埋め込みは1件で、タイトル・説明文・色・画像URLだけです。添付、複数埋め込み、JSONの直接指定、フィールド、著者、フッター、サムネイル、タイトルリンク、埋め込み日時には対応しません。
- 本文の通常URLからDiscord自身のプレビューが生じる場合はあります。Webhookの名前やアバターによる利用者のなりすましは行いません。

<a id="edit-conflicts-and-mismatches"></a>

## 編集の競合と内容不一致を理解する

**リビジョン**は保存内容の版を表します。別の編集が成功すると古いフォームになるため、新しいフォームを開いてください。同一内容の送信でも、WEFTは現在のDiscordの内容全体と保存記録を照合します。この確認には現在の権限、投稿の存在、WEFT自身の投稿であること、編集可能性も必要です。不一致なら調査のため停止し、どちらかを自動で書き換えません。

本文や対応する埋め込みが変わると、1つのリビジョンを1回更新します。現在の権限があれば別の管理者も編集でき、作成者だけの専用操作ではありません。症状ごとの確認には、[メッセージ編集の調査手順](Troubleshooting-ja#an-edit-is-stale-unchanged-or-mismatched)を使用してください。

<a id="permissions-and-uncertain-outcomes"></a>

## 結果未確認と削除・復元の扱い

送信した投稿の管理登録前に、WEFTは応答のサーバー・チャンネル・ボットの識別情報と、対応する本文・埋め込み全体を照合します。識別情報を確認できても、保存前の内容検証に失敗した場合は、その既知の投稿の削除を1回試みることがあります。識別情報が未確認なら削除は行いません。これは、DB保存の不成立を確認した後の削除とは別です。

WEFTが記録を保存し終える前に、Discordへの送信や編集が反映される場合があります。そのため、DB側に問題が起きても、未送信・未編集とは限りません。両方をまとめて自動的に元へ戻すこともできないため、応答から次を区別してください。

| 確認できた事実                  | 意味と安全な対処                                                                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 送信結果未確認                  | 送信済みの可能性があります。再送前に投稿先と運用記録を確認します。                                           |
| 送信済み・管理登録`UNCONFIRMED` | 保存された可能性があります。保存の可能性がある場合、WEFTは削除しません。再送・削除前に投稿と記録を調べます。 |
| 削除確定                        | 内容検証の失敗または保存の不成立を確認した後、既知の送信済み投稿の削除を確認しました。                       |
| 確認時に不在                    | 観測時点の不在を確認しました。WEFTによる削除の証明ではありません。                                           |
| 削除・復元の拒否                | 元に戻すための要求が拒否されました。現在の状態を調べます。                                                   |
| 削除・復元が未確認              | 結果が不明です。削除済み・復元済みと判断しないでください。                                                   |

変更の保存に失敗した場合、WEFTは安全に行えるときに、送信済み投稿の削除や変更前の内容への復元を試みる場合があります。DB結果が不明という理由だけでは変更を取り消しません。`PARTIAL`は過去の確認済み事実を記録するものであり、現在の投稿や内容が残っていることを確定しません。

調査には[結果の見方](Troubleshooting-ja#result-states)と[監査とプライバシー](Audit-and-Privacy-ja)を使用してください。コマンドの詳細は[`send`](Commands-Message-ja#message-send)、[`edit`](Commands-Message-ja#message-edit)を参照してください。
