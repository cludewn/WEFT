# スレッドコマンドの詳細

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Commands-Thread)

スレッドコマンドの入力と結果を調べるためのページです。自動クローズの設定や現在の予約クローズを確認する場合は、[`/thread status`](#thread-status)から始めてください。議論のクローズや、開いた状態の反映は、[スレッド管理](Thread-Lifecycle-ja)を参照してください。

8操作すべてがサーバー内専用で、実行者の現在の「スレッドの管理」権限（`ManageThreads`）が必要です。対象の場所やWEFT自身の権限は操作によって異なるため、各項目の「権限と場所」で確認してください。コマンドが表示されているだけでは実行許可になりません。操作結果とエラーは実行者だけに表示します。

| コマンド詳細                                   | 機能ガイド                                          |
| ---------------------------------------------- | --------------------------------------------------- |
| [`/thread close`](#thread-close)               | [スレッドのクローズと状態管理](Thread-Lifecycle-ja) |
| [`/thread open`](#thread-open)                 | [スレッドのクローズと状態管理](Thread-Lifecycle-ja) |
| [`/thread status`](#thread-status)             | [自動クローズ](Automatic-Close-ja)                  |
| [`/thread track`](#thread-track)               | [自動クローズ](Automatic-Close-ja)                  |
| [`/thread untrack`](#thread-untrack)           | [自動クローズ](Automatic-Close-ja)                  |
| [`/thread close-after`](#thread-close-after)   | [予約クローズ](Scheduled-Thread-Close-ja)           |
| [`/thread cancel-close`](#thread-cancel-close) | [予約クローズ](Scheduled-Thread-Close-ja)           |
| [`/thread bulk-close`](#thread-bulk-close)     | [スレッドの一括クローズ](Bulk-Thread-Close-ja)      |

**構文と操作方法:** 構文のコードブロックはコマンド名と引数を説明する表記で、貼り付けて実行する文字列ではありません。DiscordでWEFTのコマンド候補を選び、適切な場所で実行します。`<...>`や省略可能な引数の`[...]`は入力しません。

- **スレッド内の操作:** 一括クローズ以外は、対象スレッド内で実行します。スラッシュ引数のないコマンドでは、実行前に追加の入力は不要です。
- **クローズまでの時間:** `/thread close-after`の`after`には、`2h`などの期間を文字列で入力します。日時を選ぶ欄ではありません。
- **一括クローズのフォーム:** `/thread bulk-close`にスラッシュ引数はありません。実行すると、必須の親チャンネル選択欄と、任意の作成者選択欄・文字列の条件入力欄を開きます。フォームの送信は候補の準備までで、対象を選択して確定するとクローズを開始します。

以下の**実行登録**は、保存した予約クローズをスケジューラが実行するための準備であり、クローズ完了ではありません。保存済み・登録未確認の違いは[予約クローズ](Scheduled-Thread-Close-ja#create-replace-and-inspect)を参照してください。

以下の使用例では、利用目的と実際の入力、結果の確認を対応させています。共通のUI操作は[入力・選択・フォームの使い分け](Command-Reference-ja#read-syntax)を参照してください。`PENDING`や結果未確認の場合は、再び変更する前に[結果の見方](Troubleshooting-ja#result-states)を確認します。statusは、すべての状態反映の進捗を表示するものではありません。

## /thread close

**目的:** 有効な場合は適用対象のクローズ用プレフィックスを付け、スレッドをロックせずにアーカイブします。

**権限と場所:** 対応するロックされていない公開・アナウンススレッド、アクセス可能な非公開スレッド、フォーラム投稿内で使用します。実行者とWEFTにViewChannelとManageThreadsが必要です。

**構文:**

```text
/thread close
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

解決済みのサポートスレッドをアーカイブする場合の例です。

1. 意図したスレッド内にいることと、ロックされていないことを確認し、`/thread close`を引数なしで実行します。
2. 応答を読み、クローズ完了・すでにクローズ済みと、`PENDING`・結果未確認を区別します。
3. 完了が確定したら、Discord上の実際のアーカイブ状態と名前を確認します。適用する設定で有効な場合だけプレフィックスを付加し、ロックはしません。

処理が続いている場合は、再び変更する前に[スレッドの遅延の確認](Troubleshooting-ja#thread-delays)へ進んでください。

**結果:**

- **確認済み:** 処理結果の根拠に基づき、クローズ済み・すでにクローズ済みと返します。
- **予約への影響:** 待機中（`ACTIVE`）の予約クローズを先に取り消します。
- **処理継続中:** `PENDING`はWEFTが処理・結果確認を継続している状態です。

**制約:**

- ロック中は拒否します。EXECUTINGの予約や取消未確認では手動クローズを開始しません。確定した取消は後の失敗でも戻しません。
- 同一スレッドでクローズ・状態反映に関わる操作を繰り返すと、約10分の待機が必要になる場合があります。次の操作を計画するときはこの待機を見込み、前回の結果と現在の状態を確認してください。時間経過だけを理由に再実行しません。[同一スレッドの遅延](Thread-Lifecycle-ja#delays-and-safe-observation)では次の操作前の確認事項と、別の仕組みである`PENDING`中の操作制限も説明しています。
- DBのCLOSED記録だけではアーカイブ成功は確定しません。再クローズ時も、空文字を含む保存済みプレフィックスを保持します。

**関連:** [スレッドのクローズと状態管理](Thread-Lifecycle-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread open

**目的:** すでに開いているスレッドの状態をWEFTへ反映し、該当する保存済みクローズ用プレフィックスを先頭から1つ除去します。

**権限と場所:** すでに開いている対応スレッド内で使用します。実行者とWEFTにViewChannelとManageThreadsが必要です。既存のWEFT管理記録がなくても使用できます。

**構文:**

```text
/thread open
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

Discordで議論を再開した後、開いた状態をWEFTへ反映する必要がある場合に使います。

1. 対象スレッドがDiscordですでに開いていることを確認します。`/thread open`ではアーカイブを解除できません。
2. そのスレッド内で`/thread open`を引数なしで実行します。
3. 変更・変更なしの応答と実際の名前を確認します。該当する保存済みの先頭プレフィックスがあれば除去します。プレフィックスなしでクローズした場合や、すでに状態を反映済みの場合は、名前の変更が不要なこともあります。

`/thread status`だけでは、処理継続中の状態反映が完了したと判断できません。[結果と遅延の確認手順](Troubleshooting-ja#thread-delays)を使用してください。

**結果:**

- **変更:** 該当する保存済みプレフィックスの除去と`OPEN`保存、またはWEFT状態だけの更新を行います。
- **変更なし:** 管理記録のない対応する開いたスレッドも受け付けます。アーカイブ解除の検知により、自動で反映済みの場合もあります。
- **処理継続中:** `PENDING`は処理・確認が続く状態です。

**制約:**

- WEFTはアーカイブやロックを解除しません。先にDiscordで開いてください。古い元の名前への復元、任意の文字列の除去、自動クローズ除外の変更、予約クローズの取消は行いません。手動変更した名前に保存済みプレフィックスが先頭になければ、その名前を保持します。
- 結果未確認なら実際の状態を確認してから再試行してください。
- 直前にクローズ・状態反映に関わる操作をした場合は、[同一スレッドで約10分の待機が必要になる可能性](Thread-Lifecycle-ja#delays-and-safe-observation)を考慮してください。時間経過は完了保証ではなく、WEFTが`PENDING`の処理を続けている間は、再変更も許可しません。このコマンドはすでに開いているスレッドで使うもので、待機によってアーカイブが解除されるわけではありません。

**関連:** [スレッドのクローズと状態管理](Thread-Lifecycle-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread status

**目的:** このスレッドの自動クローズ対象設定と現在の予約クローズを確認します。

**権限と場所:** 親がある対応スレッド内で、現在の「スレッドの管理」（ManageThreads）権限が必要です。アーカイブ済みのスレッドやロック中のスレッドでも使用できます。この管理操作自体にボットのスレッド変更権限は不要です。

**構文:**

```text
/thread status
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

自動クローズされない理由を調べる場合は、該当スレッド内で`/thread status`を実行します。親が有効か、個別除外があるか、無投稿期間と記録した活動時刻、優先される予約クローズの有無を確認してください。[自動クローズの症状別確認](Troubleshooting-ja#automatic-close-not-running)に沿って、見直す設定や条件を判断します。すべてのクローズ・状態反映の進捗を表示するコマンドではありません。

**結果:**

- **自動クローズ:** 対象判定、親の有効・無効、個別除外、無投稿期間、最終投稿または計測開始時刻を表示します。
- **明示的な予約:** 現在の予約日時・実行中・なしを表示します。
- **読取専用:** 修復やDiscord履歴の走査は行いません。

**制約:** 全操作の進捗追跡ではありません。処理継続中のクローズ・状態更新、最終監査処理、終了済みの予約履歴、予約投稿は表示しません。「なし」はPENDINGの処理が完了した証明ではありません。取得失敗を「なし」とは扱いません。

**関連:** [自動クローズ](Automatic-Close-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread track

**目的:** このスレッドの自動クローズの除外設定を解除します。

**権限と場所:** 親がある対応スレッド内で、現在の「スレッドの管理」（ManageThreads）権限が必要です。アーカイブ済みのスレッドやロック中のスレッドでも使用できます。この管理操作自体にボットのスレッド変更権限は不要です。

**構文:**

```text
/thread track
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

除外していたサポートスレッドを、再び自動クローズの候補に戻す場合の例です。

1. 対象スレッド内で`/thread track`を引数なしで実行します。
2. 除外解除または除外なしという結果と、別に示される親設定に基づく対象判定を確認します。
3. 同じスレッドで[`/thread status`](#thread-status)を実行し、個別除外がないことを確認します。そのスレッドに自動クローズを適用するには、親も有効である必要があります。

親が無効の場合は、「サーバーの管理」権限で[サーバー側の設定](Automatic-Close-ja#enable-a-parent-then-exempt-individual-threads)を行います。trackを繰り返しても親は有効になりません。

**結果:**

- **除外設定:** 除外解除・除外なしと、親設定を踏まえた対象・対象外を分けて返します。
- **計測:** 有効な親で除外を解除すると操作時点から計測し、より新しい活動は保持します。再実行は既存時刻を保ち、未記録の場合だけ補います。

**制約:** 親を有効化せず、予約クローズも変更しません。親が無効なら除外だけを解除し、計測を開始しません。UNCONFIRMEDなら/thread statusで確認します。

**関連:** [自動クローズ](Automatic-Close-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread untrack

**目的:** このスレッドを自動クローズから除外します。

**権限と場所:** 親がある対応スレッド内で、現在の「スレッドの管理」（ManageThreads）権限が必要です。アーカイブ済みのスレッドやロック中のスレッドでも使用できます。この管理操作自体にボットのスレッド変更権限は不要です。

**構文:**

```text
/thread untrack
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

継続して参照するスレッドを、無投稿期間による自動クローズから除外する場合の例です。

1. 対象スレッド内で`/thread untrack`を引数なしで実行します。
2. 除外またはすでに除外という結果を確認し、[`/thread status`](#thread-status)で個別除外と、そのスレッドに自動クローズが適用されるかどうかを確認します。

明示的な予約クローズは別の設定です。予約があり、そちらも取り消す場合は[`/thread cancel-close`](#thread-cancel-close)を使用してください。untrackでは予約を取り消せず、開始済みの処理も停止しません。

**結果:** 除外またはすでに除外と返します。活動の記録時刻を保持します。親が有効でなくても操作できます。

**制約:** 明示的な予約クローズの取消、スレッドの再開、開始済み処理の停止は行いません。変更未確認なら/thread statusで確認します。

**関連:** [自動クローズ](Automatic-Close-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread close-after

**目的:** このスレッドの予約クローズを設定します。既存のACTIVE予約は置き換えます。

**権限と場所:** 開いていてロックされていない対応スレッド内で使用します。実行者とWEFTにViewChannelとManageThreadsが必要です。

**構文:**

```text
/thread close-after after:<duration>
```

**引数:**

| 引数    | 必須・任意 | 入力方法・条件                                                                                                                        |
| ------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `after` | 必須       | 正の整数と`m`、`h`、`d`のいずれかを1組の文字列で入力します。範囲は1分～365日（経過時間）です。例えば`30m`、`2h`、`7d`を指定できます。 |

**使用例:**

この操作から2時間後に、スレッドをクローズする予約を設定する場合の例です。

1. 対象の、開いていてロックされていないスレッド内で、`/thread close-after`の`after`に`2h`を入力して実行します。
2. 作成・置換の結果を確認し、返された予約IDと実行日時を控えます。待機中の予約がある場合は置換するため、別の予約が追加されるわけではありません。
3. 同じスレッドで[`/thread status`](#thread-status)を実行し、現在の予約日時を確認します。実行後は、Discord上の実際のアーカイブ状態を確認してください。

予約の保存はクローズ完了ではありません。実行登録待ちの場合は、保存済みの予約を保持し、確認してから再試行を判断してください。

**結果:**

- **保存済み:** 作成・置換、予約ID、実行日時を返します。その場でクローズしません。
- **保存済み・実行登録未確認:** 予約は保存されており、WEFTが後から実行登録を確認・修復します。

**制約:**

- スレッドごとに現在の予約は1件です。EXECUTINGは置換できません。不正な時間指定、アーカイブ済み・ロック中の対象、権限不足、保存未確認は、保存済み・登録待ちと区別します。再試行前に/thread statusを確認してください。再起動後も条件を満たす期限超過の予約は実行され得ます。
- 投稿の猶予期間は適用しません。

**関連:** [予約クローズ](Scheduled-Thread-Close-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread cancel-close

**目的:** このスレッドのACTIVEの予約クローズを取り消します。

**権限と場所:** ViewChannelと「スレッドの管理」（ManageThreads）権限を持つ人が対応スレッド内で使用します。アーカイブ済みのスレッドやロック中のスレッドでも使用できます。WEFTの変更権限は不要です。

**構文:**

```text
/thread cancel-close
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

明示的な予約日時を過ぎても議論を続けたい場合の例です。

1. スレッド内で[`/thread status`](#thread-status)を実行し、現在の予約を確認します。
2. `/thread cancel-close`を引数なしで実行します。取消が確定したか、現在の予約がないか、実行開始済みで取り消せないかを読み分けます。
3. 取消が確定したら、`/thread status`で現在の予約欄を確認します。

自動クローズの設定は引き続き適用されます。無投稿期間によるクローズも防ぐ場合は、[`/thread untrack`](#thread-untrack)を検討してください。予約がないことだけでは、他の処理継続中の操作が完了したとは判断できません。

**結果:**

- **取消・変更なし:** ID付きの取消済み、または現在の予約なしによる正常な変更なしを返します。
- **取消不可:** `EXECUTING`は実行開始済みです。
- **対象範囲:** スレッドや自動クローズ設定は変更しません。

**制約:** 取消保存が未確認なら再試行前に/thread statusで確認します。確定した取消後にキューが残っても、その予約の実行を許可するものではありません。取消は自動クローズからの除外ではありません。

**関連:** [予約クローズ](Scheduled-Thread-Close-ja) · [結果の見方](Troubleshooting-ja#result-states)

## /thread bulk-close

**目的:** スレッドを対話形式で選択し、確認した対象だけをクローズします。

**権限と場所:** 「スレッドの管理」（`ManageThreads`）が必要です。サーバー内で実行してテキスト・アナウンス・フォーラムの親チャンネルを選択します。実行者とWEFTの両方に、親と各対象のViewChannelとManageThreadsが必要です。非公開スレッドは対象外です。

**構文:**

```text
/thread bulk-close
```

**引数:**

スラッシュコマンドの引数はありません。

**使用例:**

名前に`resolved`を含み、作成から7日以上経過したサポートスレッドを確認してクローズする場合の例です。

1. サーバー内で`/thread bulk-close`を実行します。フォームの「親チャンネル」で実際のサポート用の親を選び、「スレッド名に含む文字列」に`resolved`、「作成からの経過時間」に`7d`を入力します。「スレッドの作成者」は、作成者も絞る場合だけユーザー候補から選択し、それ以外は省略します。
2. 条件を送信し、候補を確認します。この条件では、一致する候補が最初からすべて選択されています。残すスレッドの選択を解除し、すべてのページの選択を確認してください。
3. 予約取消の注意を確認し、選択した対象が正しい場合だけ「選択したスレッドを一括クローズ」を押します。
4. 結果件数とDiscord上の対象スレッドを確認します。`Skipped`は試行未開始、`Pending`は後から完了する可能性のある処理です。一括操作を繰り返す前に、[一括クローズの結果の調査](Troubleshooting-ja#bulk-close-skipped-targets)へ進んでください。

`7d`は作成からの経過時間であり、無投稿期間ではありません。候補表示や条件の送信だけではクローズしません。

**結果:**

- **フォーム:** コマンド実行直後に開きます。親チャンネルと、任意の作成者・名前の部分文字列・作成からの経過時間を指定します。
- **選択:** 候補と各ページの選択を確認して確定します。条件指定時は全候補が選択済み、条件なしでは未選択です。
- **実行:** 選択、開始、クローズ済み、すでにクローズ済み、Pending、失敗または結果未確認、Skippedの件数を返します。実行前のキャンセルでは対象を変更しません。

**制約:**

- 候補は最大50件で、1ページに10件表示します。条件フォームの送信期限は開いてから5分、候補選択画面の有効期間はその作成から別に5分です。操作しても延長せず、実行者のみ操作できます。条件はANDで、名前の部分文字列は最大100 UTF-16コード単位、経過時間の入力は最大32 UTF-16コード単位です。作成からの経過時間は1m～365dで無投稿期間とは別です。実行には1件以上の選択が必要です。
- 条件フォームの受付情報（フォームの識別と送信期限を管理する記録）と候補確認画面の記録には、起動中のアプリ全体でそれぞれ128件の上限があります。満杯なら既存セッションを追い出さず新しい受付を拒否し、取消済みの候補セッションも元の有効期限まで保持します。
- 直前の確認で対象を開始せずスキップすることがあります。開始した処理は後で完了する場合があり、クローズが失敗しても取り消した予約は戻りません。全件一括成功の保証や、処理継続中の完了を後から知らせる通知はありません。大きな一括操作の前に機能ガイドを確認してください。
