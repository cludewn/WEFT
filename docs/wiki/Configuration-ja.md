# サーバー設定

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Configuration)

サーバー設定では、WEFTのタイムゾーン、スレッド管理方針、監査通知、メッセージリンクプレビューを設定します。「サーバーの管理」（`ManageGuild`）権限で、Discordサーバーごとに設定します。導入しただけでは自動クローズは有効になりません。

<a id="defaults-and-first-choices"></a>

## 変更前に既定値を確認する

[`/config show`](Commands-Config-ja#config-show)を引数なしで実行し、現在のタイムゾーン、クローズ用プレフィックス、自動クローズの概要、監査通知先、プレビューモードを確認します。次の表で現在値と判断事項を照らし合わせ、必要な設定だけ変更してください。

詳細が必要な場合は、[`/config auto-close show`](Commands-Config-ja#config-auto-close-show)で自動クローズの設定と親チャンネル、[`/config audit-log show`](Commands-Config-ja#config-audit-log-show)で保存済みの監査通知先を確認します。どちらも引数はありません。

| 設定                     | 既定値     | 判断すること                                             |
| ------------------------ | ---------- | -------------------------------------------------------- |
| WEFTの既定タイムゾーン   | UTC        | 新しい日時入力をどの地域の時刻として解釈するか           |
| クローズ用プレフィックス | `[CLOSED]` | 以後のクローズで名前に目印となる文字列を付けるか         |
| 自動クローズの親         | なし       | どの親チャンネルで自動クローズを使うか                   |
| 無投稿期間               | 7日        | 対象の活動がない期間をどの長さにするか                   |
| ボット投稿を活動に含むか | 含めない   | 自動投稿でスレッドの無投稿期間を延ばすか                 |
| 監査通知先               | 無効       | 任意の操作通知を誰が閲覧できるようにするか               |
| リンクプレビュー         | `hybrid`   | 公開閲覧できるリンク先のメッセージを自動コピーしてよいか |

<a id="timezone-and-language"></a>

## 日時入力の設定と言語を確認する

予約投稿の現地日時を入力する前に、`Asia/Tokyo`など、地域の時刻規則を表すIANAタイムゾーン名を設定してください。`+09:00`のような数値オフセットは使用できません。

1. [`/config timezone`](Commands-Config-ja#config-timezone)を選び、`value`に`Asia/Tokyo`を入力して実行します。
2. 保存済み・変更なしの応答を確認し、`/config show`を引数なしで実行して**WEFTの既定タイムゾーン**を確認します。

既定値を変えても、保存済みの単発予約の日時や定期投稿は移動しません。日時指定や定期投稿を使う前に[タイムゾーンと日時指定](Timezones-and-Scheduling-ja)を確認してください。

タイムゾーンは言語設定ではありません。各操作は実行者のDiscord操作の言語に従い、`ja`なら日本語、その他は英語です。自動処理の出力には取得済みのサーバー言語を使い、未対応時は英語になります。

<a id="closed-prefix"></a>

## クローズ用プレフィックスを選ぶ

**クローズ用プレフィックス**は、WEFTがクローズ時にスレッド名の先頭へ付ける文字列です。今後のクローズに使う設定を選びます。

- `[DONE]`を付ける場合は、[`/config closed-prefix set`](Commands-Config-ja#config-closed-prefix-set)を選び、`value`に`[DONE]`を入力して実行します。
- プレフィックスを付けずにクローズする場合は、[`/config closed-prefix disable`](Commands-Config-ja#config-closed-prefix-disable)を引数なしで実行します。

応答を読み、`/config show`で**クローズ用プレフィックス**を確認します。無効時は「無効」と表示します。

`set`では前後の空白を除いて1～20 Unicodeコードポイントを指定し、制御文字は使用できません。空文字や空白だけの入力は無効化にならないため、明示的に`disable`を使ってください。

既存のスレッド名は変わりません。WEFTはクローズ時のプレフィックスを、使用しなかった場合も含め、開いた状態が反映されるまで保持します。そのため、再クローズで保存済みプレフィックスを使う場合があります。除去・手動変更・切り詰めは[スレッド管理](Thread-Lifecycle-ja#saved-prefixes-and-manual-names)で説明します。

<a id="automatic-close-and-exclusions"></a>

## 必要な範囲だけ自動クローズを有効にする

[自動クローズ](Automatic-Close-ja)に従い、無投稿期間、対象の親チャンネル（テキスト・アナウンス・フォーラム）と、個別スレッドを設定・確認します。有効化時に開いているスレッドを取得して計測開始時刻を設定し、取得失敗なら親を有効にしません。

サーバーの自動クローズ設定は`/config auto-close show`で確認します。個別のスレッドの状態は、対象スレッド内へ移動し、[`/thread status`](Commands-Thread-ja#thread-status)を実行して確認します。個別除外には[`/thread untrack`](Commands-Thread-ja#thread-untrack)を使います。親を外しても活動記録・除外設定は保持し、明示的な予約クローズは取り消しません。期間を短くする前に、新しい閾値が適用される活動記録を確認してください。

<a id="notifications-and-preview-policy"></a>

## 監査通知とプレビューの公開範囲を選ぶ

いずれも独立した任意の機能です。設定前にリンク先のガイドを確認してください。

| 機能                                                            | 設定例                                                               | 確認方法                    | 変更前の注意                                                                             |
| --------------------------------------------------------------- | -------------------------------------------------------------------- | --------------------------- | ---------------------------------------------------------------------------------------- |
| [監査通知](Audit-and-Privacy-ja#optional-discord-notifications) | `/config audit-log set`：`channel`で対象を選択                       | `/config audit-log show`    | メタデータが見えるため、適切な閲覧範囲を選びます。通知を無効にしてもDB監査は継続します。 |
| [メッセージリンクプレビュー](Link-Previews-ja)                  | `/config link-preview mode`：`value`で「プレビューボタンのみ」を選択 | `/config link-preview show` | 自動表示は内容のコピーです。モード変更で過去のコピーは削除しません。                     |

監査通知先のshowは、削除済みチャンネルでも保存IDを表示します。現在のDiscord権限は別に確認してください。機密性の高いサーバーでは、既定の`hybrid`を使い続ける前に、自動コピーが適切か検討してください。

<a id="confirm-changes"></a>

## 変更ごとに結果を確認する

設定変更はコマンドごとに保存されます。後から実行した別の設定変更が失敗しても、それ以前に保存が確定した変更は自動的に取り消されません。次へ進む前に各応答を確認してください。

- **変更済み:** 保存が確定しています。
- **変更なし・すでに無効:** 新しい変更が不要だった正常な結果です。
- **`UNCONFIRMED`:** 保存成功・失敗のどちらも確定していません。該当する`show`で現在値を確認し、不明なら再試行前にホスト運用者と[確認できる情報](Troubleshooting-ja#available-checks)に従って調べます。

応答を受け取れなくても、保存済みの変更は取り消されません。現在の設定は次の操作の判断に役立ちますが、その値だけでは、結果未確認だった特定の要求が保存されたことまでは証明できません。[結果の見方](Troubleshooting-ja#result-states)を参照してください。

全14操作の正確な構文・権限は[設定コマンドの詳細](Commands-Config-ja)に掲載しています。
