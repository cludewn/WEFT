# スレッドの一括クローズ

[ホーム](Home-ja) · [コマンド一覧](Command-Reference-ja) · [トラブルシューティング](Troubleshooting-ja) · [English](Bulk-Thread-Close)

一括クローズは、複数のスレッドを確認し、選択した対象だけを確定してクローズする機能です。例えば、古い解決済みのサポートスレッドを確認してからアーカイブできます。対象ごとに独立して処理するため、一部が失敗しても他の対象はクローズする場合があります。

操作は**条件フォーム→候補確認→選択→確定→集計結果の確認**の順です。フォームや候補画面を開いただけではクローズしません。

<a id="before-starting"></a>

## 対象範囲と権限を確認する

サーバー内で「スレッドの管理」権限を使います。テキスト・アナウンス・フォーラムの親チャンネルを選び、実行者とWEFTの両方に、親と各対象の現在の「チャンネルを見る」と「スレッドの管理」権限が必要です。

候補は、選択した親に属する、開いていてロックされていない公開・アナウンス・フォーラム投稿です。WEFT未管理でも対象になります。非公開・アーカイブ済みスレッドは対象外です。

<a id="build-a-preview"></a>

## 1. フォームで条件を指定する

サーバー内で`/thread bulk-close`を引数なしで実行すると、Modal（入力フォーム）がすぐに開きます。親チャンネルと、必要に応じて絞り込み条件を指定します。

| フォームの項目         | 必須・任意 | 入力方法と絞り込み条件                                                                                                                   |
| ---------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 親チャンネル           | 必須       | チャンネル選択欄で、対象のテキスト・アナウンス・フォーラムチャンネルを1件選びます。                                                      |
| スレッドの作成者       | 任意       | ユーザー選択欄でDiscordユーザーを1人選びます。スレッドの現在の作成者IDとの一致で絞り込みます。                                           |
| スレッド名に含む文字列 | 任意       | 最大100 UTF-16コード単位で入力します。大文字・小文字を区別する部分一致です。空白以外の文字を含む場合は、前後の空白も一致条件になります。 |
| 作成からの経過時間     | 任意       | 1m～365dの期間を1組入力します。入力は最大32 UTF-16コード単位です。無投稿期間ではなく、作成からの経過時間で絞り込みます。                 |

例えば、親にサポートフォーラム、名前に含む文字列に`resolved`、作成からの経過時間に`30d`を指定します。候補作成時点で作成から30日以上経過した、開いている一致スレッドを探します。最終活動からの時間ではありません。

複数の条件はすべて満たす必要があります（AND条件）。空文字・空白だけのテキストは未指定です。空白以外を含む名前の条件は前後空白も保持します。経過時間には有効なDiscord作成日時が必要で、最終投稿日時では代用しません。

フォームを送信すると、変更を行わず候補画面を作成します。0件なら選択画面はありません。**50件を超えると全体を拒否し、一部だけ表示することはありません。** 条件を追加・調整してください。

<a id="review-the-selected-subset"></a>

## 2. ページを確認して対象を選ぶ

| 制限する対象                                                    | 上限・有効期間 | 補足                                                                               |
| --------------------------------------------------------------- | -------------- | ---------------------------------------------------------------------------------- |
| <!-- fact:bulk-candidates --> 1回の候補画面に含められるスレッド | 50件           | 50件を超える場合は候補画面を作成できません。絞り込み条件を追加・調整してください。 |
| <!-- fact:bulk-page --> 1ページに表示する候補                   | 10件           | 候補は最大5ページに分けて表示されます。                                            |
| <!-- fact:bulk-session-minutes --> 候補選択画面の有効期間       | 5分            | 画面を作成した時点から計測します。ページ移動や選択操作をしても延長されません。     |

1. 親、条件、候補数を確認します。
2. 初期選択を確認します。任意の作成者・名前・経過時間の条件を1つでも指定した場合は全候補が選択済みで、それらを指定しない場合は未選択です。
3. 現在のページの選択を変更します。「このページの選択を解除」はそのページだけに適用します。
4. 前へ・次へで他のページを確認します。ページを離れても選択は保持します。
5. 確定前に合計選択数を確認します。候補が1件でも、実行には1件以上の選択が必要です。

フォームと操作部品は実行者専用です。条件フォームの送信期限は開いてから5分、候補画面はその作成から別に5分です。操作しても有効期間は延長しません。候補IDと作成日時の基準は固定し、後から一致したスレッドを追加しません。実行前のキャンセルでは対象の処理を開始しません。

<a id="confirm-selection"></a>

## 3. 選択した対象を確定する

**確定前の注意:** クローズはロックせずアーカイブします。待機中の予約クローズを取り消す場合があり、その後のクローズが失敗・処理継続中でも取消は戻りません。全件をまとめて元に戻す仕組みはありません。

確定時に選択対象を固定します。試行前に状態・権限・条件を再確認するため、選択していても開始できない場合があります。未選択の候補には、この一括操作からのクローズ、予約取消、クローズ監査はありません。

<a id="confirm-and-interpret-the-summary"></a>

## 4. 集計結果を読み取る

| 集計項目                         | 件数の意味                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 選択                             | 確定時に選択されていた対象の件数です。候補全体の件数ではありません。                                         |
| 開始                             | この一括操作で実際に処理を開始した対象の件数です。                                                           |
| 閉じた対象・すでに閉じていた対象 | クローズ済み・すでにクローズ済みと確認できた処理結果です。DBの`CLOSED`記録だけで数えるものではありません。   |
| 処理継続中（Pending）            | WEFTが開始済みの処理を継続しており、後から完了する可能性があります。                                         |
| 失敗または結果未確認             | 処理全体の完了は確認できていません。Discord上では変更されている可能性があります。                            |
| スキップ（Skipped）              | この一括操作では対象の処理を開始していません。条件の変化、別の操作の処理継続、予約の実行中などが該当します。 |

開始件数は、クローズ済み・すでにクローズ済み・処理継続中・失敗または結果未確認の合計です。選択件数は開始とスキップの合計です。

スキップはクローズ完了ではありません。DBの`CLOSED`記録だけでも完了は確定しません。権限変更後の情報漏えいを防ぐため、集計には対象名を含めません。

選択した実際のスレッドをDiscordで確認してください。Pendingは待機して観察します。後から完了を知らせる通知はありません。失敗または結果未確認は、応答と現在の状態を確認してから次の一括操作を判断します。**一括全体をすぐに繰り返さないでください。**

<a id="limits-and-restart"></a>

## 実行制限・遅延・再起動

直前に操作したスレッドを含む場合は、一括操作を確定する前や、次の操作を計画する際に、[同一スレッドでの待機の注意](Thread-Lifecycle-ja#delays-and-safe-observation)を確認してください。同じスレッドでクローズ・状態反映に関わる操作を繰り返すと、約10分の待機が必要になる場合があります。短時間に操作を繰り返さないでください。約10分は目安であり、その時間で必ず操作できるようになるわけではありません。再試行前に開始済み処理を確認します。`Pending`はそれ以降も継続する場合があり、時間経過だけで`Skipped`や失敗にはなりません。

- 全セッション合計で、未完了の対象スレッド処理は最大3件です。3件はセッション数ではなく対象処理数であり、コマンド間の固定クールタイムではありません。
- 別に、条件フォームの受付情報（フォームの識別と送信期限を管理する記録）と候補確認画面の記録を、起動中のアプリ全体でそれぞれ最大128件管理します。上限では既存セッションを追い出さず、新しい受付を拒否します。確定・取消済みの候補セッションも元の有効期限まで保持するため、取消直後に空きができるとは限りません。
- 確定から5分後ちょうどまでの開始可能期間を過ぎると、新たな試行を止めます。開始済み処理は継続します。
- 対象ごとの最初の結果を待つ時間は最大15秒です。集計時点で処理全体が確定しているとは限りません。
- 再起動でフォームと選択画面は無効になり、未開始対象は再開しません。完了した変更は残ります。
- 操作部品は古い状態・権限変更・取得不能などでも無効になるため、有効期限切れだけと判断しないでください。

開始済み対象と[結果の見方](Troubleshooting-ja#result-states)を確認してから、新しい候補を作成してください。正確な権限とコマンド仕様は[`/thread bulk-close`](Commands-Thread-ja#thread-bulk-close)を参照してください。
